## 상태값
- **편집 중(Draft)**: 업로드~파라미터 수정(F2~F5) 중인 상태. 서버에 저장됨(질문2 팀 답변: "서버에 상태 저장해야 돼").
- **확정됨(Finalized)**: F6(확정) 버튼을 눌러 결과 페이지로 넘어간 상태.
- 전이: Draft --(F6 확정 버튼)--> Finalized · Finalized --(편집으로 돌아가기 버튼)--> Draft (질문2 팀 답변: "편집 중 상태로 돌아가는 거야")

※ [?] 질문2("서버에 상태 저장해야 돼")와 질문7("비로그인 구간은 브라우저 로컬 저장소만, 서버 세션 없음")이 서로 살짝 다른 방향처럼 보인다 — 로그인 전(F2~F7)까지는 결국 로컬 저장소 기준이 최종 답이라고 이해했지만, Draft/Finalized라는 "상태값" 자체를 서버가 전혀 모르는 것인지(완전히 프론트엔드+로컬저장소로만 관리) 아니면 서버가 어떤 형태로든 임시로 알고는 있는 것인지는 명확히 정리되지 않았다. 구현 설계 단계에서 다시 확인이 필요할 수 있어 [?]로 남긴다.

※ [거절 → 재확정] 비로그인 상태의 저장 방식: 처음엔 "익명 세션 ID로 서버 임시 저장 후 로그인 시 계정에 연결"을 [제안]했으나, 질문7 팀 답변("그냥 브라우저 로컬 저장소만 쓰고 서버 세션은 안 쓰는 쪽을 원해.")으로 거절되었다. **[채택]** 비로그인 구간(F2~F7, 업로드~다운로드)은 브라우저 로컬 저장소(localStorage 등)에만 저장하고 서버 세션은 쓰지 않는다. F8(프리셋 저장, 로그인 필요)부터는 서버에 계정과 함께 저장한다.
